# 品質目標

測定できる目標だけを書き、測定していない項目を達成済みとして書きません。この文書は、品質の目標値、根拠、測定方法、実測値、既知の制約を定義します。

目標は次の3つに分けて扱います。

```text
外部の基準              — WCAG 2.2、Core Web Vitals など、外部で定義された基準
このアプリの品質基準     — このアプリがリリースの基準として採用する値
エンジニアリング予算     — 実測にもとづく、実装上の目安
```

状態（Status）は次のいずれかで書きます。作業中のメモは「根拠・メモ」の欄に書き、Status には書きません。

```text
Pass            目標を満たしている
Fail            目標を満たしていない
Not measured    測定していない
```

目標値のうち「このアプリの品質基準」と「エンジニアリング予算」は、2026-10-15 の実測をもとにした提案です。

## 1. アクセシビリティ

### 1.1 目標

| 目標                                                                                  | 分類                            |
| ------------------------------------------------------------------------------------- | ------------------------------- |
| WCAG 2.2 AA に準拠する                                                                | 外部の基準                      |
| 通常の文字のコントラスト比 4.5:1 以上、大きな文字は 3:1 以上（WCAG 2.2 SC 1.4.3）     | 外部の基準                      |
| 操作できる要素は 24×24 CSS px 以上、または規定された例外に当たる（WCAG 2.2 SC 2.5.8） | 外部の基準                      |
| 主要な操作の要素は 44×44 CSS px 以上                                                  | このアプリの品質基準            |
| キーボードだけで最後まで遊べる                                                        | 外部の基準（WCAG 2.2 SC 2.1.1） |
| 動きを減らす設定（`prefers-reduced-motion`）のときは大きな動きを省く                  | このアプリの品質基準            |

### 1.2 測定方法

2026-10-15 に測定しました。本番ビルド（`npm run build` の後に `npm run preview`）を `http://localhost:4173/taikutsu/` で配信し、Playwright で操作した Chromium に axe-core 4.10.2 を読み込んで検査しました。

- 画面幅: 390×844、768×1024、1133×744、1440×900
- 状態: イントロ（表示直後）、戦闘（「たたかう」の後）、ギャラリー（5回攻撃した後）
- 演出が落ち着いた状態を検査するため、動きを減らす設定を有効にして測定
- 検査の対象: axe-core の `wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa`、`wcag22aa`、`best-practice` のルール
- 操作できる要素の大きさ: 表示中で操作できる `button`、`a[href]` の表示上の大きさを、390×844 と 1440×900 の3つの状態で測定

### 1.3 実測値

| 目標                             | Status       | 根拠・メモ                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WCAG 2.2 AA に準拠する           | Fail         | axe-core が、下の2項目（コントラスト、操作できる要素の大きさ）の違反を検出。実機のスクリーンリーダーでの確認と、手動での全項目の確認はしていない                                                                                                                                                                                                                                                         |
| 文字のコントラスト比             | Fail         | 4つの文字が 4.5:1 に届かない。戦闘画面の「退屈のかたまり」3.33:1（12px）、戦闘画面の見出しの上の英字「A SMALL CHANGE IN A BORING WORLD.」3.33:1（10px）、「TA • IKUTSU」2.5:1（10px）、イントロの地図データのクレジット 2.89:1（10px、横並びのときに表示）。背景に画像がある文字や、ほかの要素と重なっている文字などは axe-core が自動判定を保留する（incomplete）ため、それらの文字の比は確認していない |
| 操作できる要素が 24×24 px 以上   | Fail         | ギャラリーの作品を選ぶ点（10個）が 9×9 px。それ以外の要素は 24 px 以上                                                                                                                                                                                                                                                                                                                                   |
| 主要な操作の要素が 44×44 px 以上 | Fail         | スキルの行と「たたかう」は 44 px 以上。44 px に届かないのは、効果音のボタン（40×40）、「ほかのスキルを見る」（136.8×33.1）、ギャラリーの「前の作品」「次の作品」（390×844 で 34×34、1440×900 で 38×38）と作品を選ぶ点（9×9）                                                                                                                                                                             |
| キーボードだけで最後まで遊べる   | Not measured | スキル一覧の上下の矢印キーでの移動と確定、ギャラリーの左右の矢印キーでの切り替えは、自動テストとブラウザでの操作で確認済み。全画面を通した Tab キーの移動順は確認していない                                                                                                                                                                                                                              |
| 動きを減らす設定への対応         | Pass         | 動きを減らす設定を有効にした状態で、イントロから再戦までの流れを自動テスト（`src/pages/HomePage.test.tsx`）とブラウザでの操作で確認                                                                                                                                                                                                                                                                      |

## 2. パフォーマンス

### 2.1 Lighthouse（このアプリの品質基準）

目標:

```text
Performance      >= 90
Accessibility    >= 95
Best Practices   >= 95
```

測定条件:

- 本番ビルド（`npm run build` の後に `npm run preview`）を `http://localhost:4173/taikutsu/` で配信
- Lighthouse CLI 12.8.2、ヘッドレスの Chrome for Testing、モバイルの設定（`--form-factor=mobile --screenEmulation.mobile --throttling-method=simulate`）
- 対象はアプリを開いた直後（イントロ）の状態
- 3回実行して中央値を報告する（最良の回は選ばない）

2026-10-15 の実測:

```text
1回目: Performance 58 / Accessibility 100 / Best Practices 100
2回目: Performance 73 / Accessibility 100 / Best Practices 100
3回目: Performance 65 / Accessibility 100 / Best Practices 100
```

| 目標                 | Status | 根拠・メモ                                                                                                                   |
| -------------------- | ------ | ---------------------------------------------------------------------------------------------------------------------------- |
| Performance >= 90    | Fail   | 中央値 65（58、73、65）                                                                                                      |
| Accessibility >= 95  | Pass   | 中央値 100。Lighthouse はアプリを開いた直後の画面だけを自動判定するため、§1 の戦闘画面とギャラリーの違反はこの値に含まれない |
| Best Practices >= 95 | Pass   | 中央値 100                                                                                                                   |

Lighthouse のスコアは測定環境での値（lab data）で、実際の利用者の体験そのものを保証しません。

### 2.2 Core Web Vitals（外部の基準）

目標（外部の基準の「Good」の値をそのまま採用）:

```text
LCP <= 2.5 s
INP <= 200 ms
CLS <= 0.1
```

| 目標          | Status       | 根拠・メモ                                                                                                   |
| ------------- | ------------ | ------------------------------------------------------------------------------------------------------------ |
| LCP <= 2.5 s  | Not measured | 実際の利用者のデータ（field data）を集める仕組みがない。参考として、§2.1 と同じ条件の lab data は 5.0〜5.2 s |
| INP <= 200 ms | Not measured | field data がない。lab data の TBT（240〜530 ms）から INP は推定しない                                       |
| CLS <= 0.1    | Not measured | field data がない。参考として、lab data は 0                                                                 |

### 2.3 JS バンドルの予算（エンジニアリング予算）

目標:

```text
最初に読み込む JS（gzip 後） <= 350 kB
```

根拠: 2026-10-15 の `npm run build` で、JS は1つのチャンクで、元の大きさ 1,132.68 kB、gzip 後 341.19 kB（Vite の出力）でした。このうち、同梱しているゲームのデータ `data/gameIntros.json` は、単体で gzip すると約 108 KiB です。今の構成のまま大きくしないための予算として、実測値にわずかな余裕を持たせた 350 kB を提案します。

| 目標                                  | Status | 根拠・メモ                                      |
| ------------------------------------- | ------ | ----------------------------------------------- |
| 最初に読み込む JS（gzip 後）<= 350 kB | Pass   | 341.19 kB（2026-10-15、`npm run build` の出力） |

## 3. 既知の制約

- **バンドルサイズ**: JS が1つのチャンクで、元の大きさが 500 kB を超えるため、ビルドのたびに Vite が警告を出します。gzip 後の 341.19 kB は、モバイルの Lighthouse の Performance が伸びない一因です。ギャラリーとゲームのデータを後から読み込む形にすれば最初の読み込みは軽くなりますが、撃破後に通信が発生し、通信に失敗したときの表示も新たに必要になります。
- **Lighthouse の Performance**: 2026-10-15 の測定では、最大の表示要素（LCP）がイントロの区画（背景の画像は約 413 kB）で、表示まで 5.0〜5.2 s かかりました。JS の実行にメインスレッドを約 1.4 s 使い、未使用の JS が約 121 KiB あると判定されています。
- **`AudioContext` の警告**: Tone.js が読み込み時に AudioContext を作るため、ブラウザの開発者ツールに「ユーザーの操作の前には開始できない」という警告が2件出ます。効果音はユーザーの操作の後に `Tone.start()` で開始するので、動作には影響しません。警告をなくすには、Tone.js 自体を後から読み込む必要があります。
- **アクセシビリティ**: §1.3 の Fail の項目（コントラストの不足、ギャラリーの点の大きさ、44 px に届かない操作の要素）と、ギャラリー表示中に h1 がないことは、未解決です。
- **確認していない環境**: 実機のスマートフォンとタブレットでの操作、Safari と Firefox での表示、スクリーンリーダーでの実際の読み上げ、効果音が実際に鳴ることは確認していません。画面サイズごとの表示は、Chromium で画面サイズを指定して確認しています。

参考にした基準:

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- [Core Web Vitals（web.dev）](https://web.dev/articles/vitals)
- [Lighthouse のスコアの算出（Chrome for Developers）](https://developer.chrome.com/docs/lighthouse/performance/performance-scoring)

このアプリ独自の基準（Lighthouse の 90/95/95、44×44 px、350 kB の予算）を、WCAG や Core Web Vitals の必須要件として示すことはしません。
